# 커스텀 탈것(펫) · 가챠 상점 개발 계획

작성: 2026-11-01. 상태: **계획 수립 / 미구현**.
대상: 이 프로젝트의 Minecraft Java Edition / Paper 1.21.11 서버.
이 문서는 원본 띵타이쿤의 확인된 펫 시스템이 아니라 사용자 요청을 바탕으로 한 자체 설계입니다.

## 1. 확정 요구와 제안의 경계

**사용자 확정 요구**

- S / A / B / C 네 등급의 탑승 가능한 펫.
- S등급 당첨 확률은 **1%**.
- 마을 안에 펫을 뽑는 가챠 상점.
- 모든 펫은 커스텀 제작.
- 설계를 MD로 보관.

**이 문서의 제안값**

- A 9%, B 30%, C 60%. 출시 후보 12종.
- 인게임 골드 사용, 1회 3,000골드의 테스트 가격.
- 독립 추첨, 천장/확률 보정 없음, 중복은 꾸미기용 조각으로 전환.
- 기본 이동 성능은 등급 간 동일. 희귀도는 디자인·연출·수집 가치 중심.

확정되지 않은 값은 아래 설정 초안과 함께 조정할 수 있습니다. 이번 작업에서는 모델 제작·플러그인 수정·서버 배포를 하지 않습니다.

## 2. 플레이 흐름

마을의 **별빛 펫 연구소** 방문 → 펫 안내원 우클릭 → 확률·전체 목록·가격 확인 → 1회 뽑기 확인 → 서버에서 결과 확정/저장 → 알 부화 연출 → 펫 도감 등록 → 소환/탑승.

일반 유저는 NPC와 보유 펫 메뉴를 사용합니다. 상점 열기/지급/회수/로그 조회 명령어는 `maitycoon.admin` 전용으로 둡니다. 일반 유저용 도움말과 자동 완성에 관리자 명령어를 노출하지 않습니다.
첫 탑승 방법은 안내원에게 무료 시험 탑승으로 배웁니다. 시험 펫은 소유 도감·추첨·중복 조각에 포함하지 않고 지정된 짧은 구간에서만 사용합니다.

## 3. 등급 확률과 추첨 규칙

| 등급 | 등급 확률 | 출시 후보 수 | 등급 내 선택 방식 | 특정 펫의 최종 확률 |
|---|---:|---:|---|---:|
| S | **1% (확정)** | 2 | 균등 | 각 0.5% |
| A | 9% (제안) | 3 | 균등 | 각 3% |
| B | 30% (제안) | 3 | 균등 | 각 10% |
| C | 60% (제안) | 4 | 균등 | 각 15% |
| 합계 | 100% | 12 | | 100% |

### 구현 규칙

- 서버에서 0~9,999의 정수를 균등 추첨: S `[0,100)`, A `[100,1000)`, B `[1000,4000)`, C `[4000,10000)`.
- 등급을 먼저 선택한 뒤 그 등급의 펫 중 하나를 별도 균등 추첨합니다. 펫 수가 늘어도 S 전체 확률은 1%를 유지합니다.
- 소유 여부, 최근 결과, 플레이 시간, 결제액, 서버 인원은 확률에 영향을 주지 않습니다.
- 첫 버전은 서버 내부 난수원(`SecureRandom` 후보)을 사용합니다. 애니메이션 진행률이나 클라이언트 입력으로 결과를 고르지 않습니다.
- UI 표시 확률과 추첨은 같은 확률표에서 생성합니다. 음수·합계 오류·빈 등급·S 가중치 100 미일치는 활성화를 막습니다.
- 거래에 확률표 버전과 결과를 함께 저장합니다. 설정 변경은 진행 중인 거래의 결과를 바꾸지 않습니다.
- **천장, A 이상 확정 10연차, 중복 재추첨 없음**. 이를 추가하면 표시 확률과 실제 확률의 의미가 달라지므로 별도 설계가 필요합니다.
- 초기 출시는 1회 뽑기만 제공합니다. 10회 묶음은 개별 10회와 같은 확률·개별 거래 결과 보존을 검증한 뒤 추가합니다.

### 유저에게 설명할 내용

S 1%는 100회 중 1회 확정이 아닙니다. 독립 추첨 기준으로 적어도 한 번 S를 얻을 확률은 `1 − 0.99^n`입니다.

| 횟수 | S를 한 번 이상 얻을 확률 |
|---|---:|
| 10회 | 약 9.56% |
| 100회 | 약 63.40% |
| 300회 | 약 95.10% |

첫 S까지의 평균은 100회이지만 개인에게 보장되는 횟수가 아닙니다. 3,000골드 테스트 가격에서는 평균 비용이 300,000골드이므로 실제 농사 수익과 땅 구매 진행을 보고 가격을 확정해야 합니다.

## 4. 커스텀 펫 라인업 — 출시 후보

전 종 자체 3D 모델·텍스처·아이콘·알 카드·애니메이션을 제작합니다. 바닐라 동물의 이름이나 색만 바꾼 것을 완성 펫으로 취급하지 않습니다.
모델 형태는 탑승자 자세와 작은 길을 통과하는 크기를 고려합니다. 아래 이름은 작업용입니다.

| 등급 | 작업명 / ID | 디자인 | 대표 연출 |
|---|---|---|---|
| C | 새싹 멧돼지 / `sprout_boar` | 둥근 몸, 새싹 갈기, 나뭇잎 안장 | 달릴 때 귀와 잎 흔들림 |
| C | 우유 송아지 / `milk_calf` | 짧은 다리, 우유빛 무늬, 작은 방울 | 고개 갸웃·방울 흔들림 |
| C | 통통 오리 / `plump_duck` | 넓은 발, 둥근 몸, 짚 안장 | 뒤뚱 걷기 |
| C | 밤송이 고슴도치 / `chestnut_hedgehog` | 등 가장자리 밤송이 가시, 평평한 안장 자리 | 코 킁킁·가시 가벼운 움직임 |
| B | 당근 토끼 / `carrot_hare` | 큰 귀, 당근색 스카프, 낮은 안장 | 귀 튕김·짧은 점프 |
| B | 버섯 여우 / `mushroom_fox` | 버섯 모양 꼬리 장식, 크림/적갈색 | 꼬리 흔들기 |
| B | 호박 거북 / `pumpkin_tortoise` | 호박 등껍질, 줄기 손잡이 | 등껍질 틈에 따뜻한 빛 |
| A | 꽃사슴 / `blossom_stag` | 꽃가지 뿔, 목재/꽃잎 안장 | 작은 꽃잎 파티클 |
| A | 구름 알파카 / `cloud_alpaca` | 구름 같은 털, 하늘빛 장식 | 착지 시 작은 구름 |
| A | 달빛 늑대 / `moon_wolf` | 남색 털, 은빛 갈기, 초승달 장식 | 달빛 발자국 |
| S | 별빛 용 / `starlight_dragon` | 둥근 소형 용, 별무늬 비늘, 접힌 날개 | 별 궤적·소환 별자리 |
| S | 황금 불사조 / `golden_phoenix` | 지상 달리기형 새, 금빛 볏과 긴 꼬리 | 금빛 깃털·부화 광륜 |

S의 날개와 부유 표현은 시각 효과입니다. **첫 버전에는 자유 비행·수면 이동·전투 능력이 없습니다.** 모든 종은 같은 지상 이동 규칙을 따릅니다.

### 제작 공통 규격

- 로우폴리 픽셀 스타일, 흙·나무·식물 중심의 기존 농사 미술과 어울리는 색감.
- 종마다 구분되는 실루엣. A/S는 단순 색 변경보다 부위와 애니메이션 차이를 줍니다.
- 등급 색: C 회백색 / B 초록 / A 보라 / S 금색. 색과 함께 등급 글자를 항상 표기합니다.
- 텍스처 64×64를 기본 후보로, S의 세부 표현은 128×128까지 검토합니다. 실제 모델 엔진/팩 경로와 성능 검증 후 확정합니다.
- 상태: 대기, 걷기, 달리기, 점프, 착지, 소환, 회수. 같은 이동 주기를 공유하되 귀·꼬리·날개의 보조 움직임은 종별 제작합니다.
- 탑승 좌표, 시선 높이, 발 접지, 회전 중심, 바운딩 크기를 모델별 메타데이터로 둡니다.
- 원본 편집 파일, 내보낸 모델, 텍스처, 아이콘, 애니메이션, 권리/제작 출처 기록을 함께 보관합니다.

## 5. 등급과 이동 성능

희귀 펫이 농사 생산량·시세·수확 보너스까지 높이면 가챠가 필수 성장 수단이 됩니다. 첫 버전은 이동 편의와 꾸미기에 집중합니다.

- 기본 속도·점프·탑승 가능 범위는 전 등급 동일. 예비 목표는 걷기보다 편한 지상 이동이며 실제 속도는 시제품에서 결정합니다.
- 외형과 움직임이 느린 거북처럼 보여도 실제 이동 성능은 동일하게 맞춥니다.
- S는 소환 연출, 전용 발자국, 이름표 장식, 도감 프레임으로 차별화합니다.
- 공격, 자동 수확, 추가 드롭, 골드 획득 배수, 펫 인벤토리는 첫 버전에서 제외합니다.
- 펫이 죽거나 소멸해도 보유권은 사라지지 않습니다. 위험 상황에서는 회수하고, 플레이어의 정상 게임 규칙은 유지합니다.

## 6. 마을 가챠 상점과 UI

### 배치

마을 확장 예정 구역에서 기존 상점·공용 밭·길과 겹치지 않는 위치를 선정합니다. 좌표는 현 월드와 `VillageBuilder` 배치를 확인한 뒤 확정합니다.
건물 콘셉트는 작은 목조 연구소 + 부화 기계 + 알 진열대 + 짧은 시험 탑승 마당입니다. 기존 마을 전체를 재생성해서 설치하지 않습니다.
상점 NPC의 ID는 `pet_gacha` 후보이며, 기존 `Village`의 NPC 작업 연결 방식을 재사용합니다. 장식용 전시 펫은 일반 펫과 별도 태그로 관리하고 상시 움직이는 수를 제한합니다.

### 메인 화면

- 상단: `별빛 펫 연구소`, 보유 골드.
- 중앙: 대표 알, 전체 등급 확률, 1회 가격.
- 하단: `1회 뽑기`, `전체 펫 보기`, `내 펫`, `최근 결과`, `닫기`.
- 확인 화면: 최종 비용, 차감 후 잔액, S 1%, 독립 추첨/중복 처리 안내.
- 전체 목록: 종별 등급·개별 확률·보유 여부·3D 미리보기 진입.
- 부족한 골드는 명확히 표시하며 자동 재구매나 반복 결제를 하지 않습니다.

### 결과 연출

제안 길이 약 3초. 알 흔들림 → 균열 → 등급 색 공개 → 펫 이름/신규·중복 여부 표시.
연출은 저장된 결과를 보여 주기만 합니다. 닫기·연출 건너뛰기·접속 종료로 재추첨하거나 결과를 잃지 않습니다.
S 전 서버 알림은 운영 옵션으로 둡니다. 이미 획득한 결과의 알림이 재접속마다 반복되지 않게 합니다.
반복 섬광과 과도한 화면 흔들림을 피하고 `연출 간소화` 옵션을 제공합니다.

리소스팩이 없으면 기본 GUI로 확률 확인과 보유 목록 조회는 가능합니다. 커스텀 외형을 볼 수 없다는 사실을 보여 주고 첫 버전에서는 추첨과 탑승을 제한하는 안을 권장합니다. 팩을 다시 받을 안내를 제공하고, 이미 소유한 펫은 보존합니다. 제한 여부는 출시 전에 운영 정책으로 확정해야 합니다.

## 7. 재화와 중복

### 비용

인게임 골드 1회 3,000을 테스트 기본값으로 제안합니다. 자동 재파종·트랙터와 경쟁하는 즈코인 소비는 첫 버전에서 피합니다.
실제 서버의 시간당 농사 순수익, 신규 유저 땅 구매 비용, 반복 뽑기 횟수를 측정해 조정합니다. 현금 구매·환전·유저 간 거래는 이 계획 범위에 없습니다.

### 중복 처리

종별 한 번의 보유권을 등록합니다. 같은 종이 다시 나오면 등급별 펫 조각을 지급합니다.
제안 지급량: C 1 / B 3 / A 10 / S 30. 숫자는 밸런스 테스트 대상입니다.
조각은 이름표 테두리, 안장 장식, 소환 효과 등 **꾸미기**에만 사용합니다. 추가 추첨권·골드 환급·등급 승급·S 확정 교환으로 연결하지 않습니다.
따라서 S 획득 경로를 몰래 추가하거나 추첨의 1% 의미를 바꾸지 않습니다. 중복 S라도 결과 기록에는 S 당첨으로 남깁니다.

## 8. 보유·소환·탑승 규칙

- 보유 펫 메뉴는 안내원/기존 도움말 메뉴에서 진입. 기존 F 키 동작을 덮어쓰지 않습니다.
- 1인당 소환 펫 1마리. 첫 버전은 소환 → 주인이 우클릭해 탑승 → 웅크리기로 하차 → 회수입니다.
- 따라다니는 동행 모드는 별도 단계로 둡니다. 첫 버전의 미탑승 펫은 안전 위치에 대기하고, 주인과 멀어지거나 일정 시간이 지나면 회수합니다.
- 주인 외 탑승·이름 변경·회수 불가. 다른 플레이어를 밀거나 길을 막지 않게 충돌 정책을 설정합니다.
- 상점 실내·금지 구역·좁은 공간에서는 소환을 막거나 안전하게 회수합니다. 경작지 훼손과 작물 밟기는 막습니다.
- 타인 토지 접근은 플레이어의 이동 정책을 따르되, 탑승을 통해 문·울타리·보호 블록을 우회하지 않게 검사합니다.
- 하차 위치는 머리 공간, 바닥, 위험 블록을 검사합니다. 안전한 곳이 없으면 이동을 정지하고 최근 안전 위치로 복귀시키는 정책을 검증합니다.
- 로그아웃·사망·월드 이동·장거리 순간이동·청크 언로드·플러그인 종료 시 런타임 엔티티를 정리합니다. 재접속 시 보유권만 복원하고 자동 탑승하지 않습니다.
- 물·용암·차원문·추락 경계는 시제품 테스트에 포함합니다. 낙하 직전 소환/회수로 피해를 지우는 악용을 막습니다.

- [CustomCrops](../../src/main/java/kr/maitycoon/CustomCrops.java): 커스텀 모델 ID, `ItemDisplay` 활용 참고.
- [TransactionJournal](../../src/main/java/kr/maitycoon/TransactionJournal.java): 미완료 거래 추적.
- [ProfileStore](../../src/main/java/kr/maitycoon/ProfileStore.java): 재화 저장과 데이터 이행 참고.

작물의 정적인 `ItemDisplay`가 동적 탈것 제어·관절 애니메이션까지 해결해 주는 것은 아닙니다.

### 첫 검증안

**이동을 담당하는 탑승 엔티티 + 커스텀 모델 표시 계층**을 분리합니다.
바닐라에서 조종 가능한 엔티티를 이동 기반으로 사용하고 겉모습은 자체 모델로 표시하는 방식을 먼저 검증합니다. 숨긴 기반 엔티티와 모델의 탑승 좌표·이동·회전·점프가 일치해야 합니다.
일반 리소스팩만으로 모든 엔티티 모델과 탑승 입력을 마음대로 교체할 수 있다고 가정하지 않습니다. 정확한 API, 패킷 처리 필요 여부, 1인칭 시야, 애니메이션 가능 범위는 **Paper 1.21.11 실클라이언트 시제품**에서 확인합니다.
직접 구현이 지나치게 복잡하면 모델/애니메이션 엔진을 별도 비교합니다. 의존 플러그인·라이선스·배포 허용·버전 호환·운영 비용을 확인하기 전 특정 엔진 채택을 확정하지 않습니다.

### 신규 모듈 후보

| 모듈 | 책임 |
|---|---|
| `PetCatalog` | 종, 등급, 모델 ID, 탑승 좌표, 연출 정의 |
| `PetGacha` | 검증된 확률표와 순수 추첨 로직 |
| `PetStore` | 보유 종, 조각, 선택 펫, 결과 수령 상태 |
| `PetGachaMenu` / `PetCollectionMenu` | 확률·확인·결과·보유 목록 |
| `PetService` | 소환·회수·엔티티 수명과 권한 |
| `PetMountController` | 이동·하차·위험 위치·다른 플러그인과의 조율 |

팩 리소스는 `maitycoon:pet/<id>/...`처럼 작물과 분리된 이름을 사용하고, 펫 ID는 출시 후 임의 변경하지 않습니다.

## 10. 추첨 저장과 복구 — 구현 필수 조건

추첨은 골드와 컬렉션을 함께 바꾸므로 기존 거래 기록을 호출하는 것만으로 완전한 원자성이 생긴다고 가정하지 않습니다.

1. 플레이어별 거래 잠금. 잔액, 팩 적용, 기능 상태, 요청 중복 여부 검사.
2. 거래 ID 생성 후 1번만 추첨. 비용, 확률표 버전, 등급, 종, 중복 여부, 차감 전후 잔액과 지급 예정 조각을 내구성 있는 준비 기록에 저장.
3. 골드 차감과 보유/조각 변경을 적용. 각 저장소에 적용된 거래 ID를 기록해 같은 거래가 다시 적용되지 않게 설계.
4. 두 저장소 적용 완료를 확인하고 거래 완료 기록. 이후 결과 연출.
5. 접속 종료 시 미표시 결과는 다음 접속/결과 메뉴에서 표시. 이미 확정된 결과를 재추첨하지 않음.

프로필과 펫 파일이 분리되면 중간 저장 실패를 복구할 수 있어야 합니다. 단계 판정이 불명확한 거래는 관련 계정의 추가 추첨을 잠그고 관리자 확인 대상으로 남깁니다. 확인할 수 없는 상태에서 자동 환급과 자동 지급을 동시에 실행하지 않습니다.
추첨 이력 필드: 거래 ID, UUID, 시각, 확률표 버전, 가격, 결과 등급/종, 신규 여부, 중복 조각, 적용 상태, 결과 알림 상태.
서버 엔티티 UUID는 영구 보유권이 아닙니다. 소유권은 저장소에 두고, 런타임 엔티티에는 주인·종·소환 세션 태그를 붙입니다.

## 11. 설정 초안 — 미적용

```yaml
pets:
  enabled: false
  require-pack: true
  active-limit: 1
  gacha:
    currency: gold
    price: 3000
    weights: {S: 100, A: 900, B: 3000, C: 6000} # 합계 10000, S 100 고정 검증
    table-version: launch-v1
    pity: false
    duplicate-shards: {S: 30, A: 10, B: 3, C: 1}
  visuals:
    reduced-effects: false
    announce-s: false
```

확률·목록·확인 화면은 이 설정과 동일한 검증된 카탈로그로 생성합니다. 종별 모델·애니메이션 파일 누락 시 해당 종을 몰래 빼고 재분배하지 않고, 추첨 기능을 비활성화해 알려야 합니다.

## 12. 단계별 개발과 완료 기준

| 단계 | 결과물 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 0. 기술 시제품 | 새싹 멧돼지 1종, 탑승 기반, 테스트 팩 | 이동·회전·점프·안전 하차·팩 실패·엔티티 정리 실게임 검증 |
| 1. 추첨/저장 | 네 등급 확률, 더미 결과, 거래/중복 처리 테스트 | 경계값·실패 복구·재실행으로 골드/펫이 복제되지 않음 |
| 2. 최소 통합 | 등급별 1종씩, 상점 NPC, 확인/결과/컬렉션 | 실제 일반 유저가 명령어 없이 뽑고 소환/탑승 가능 |
| 3. 아트 확대 | 12종 모델·아이콘·알·7개 상태 애니메이션 | 전 종 시야·탑승점·개별 확률 검수, 12종 확률표 공개 |
| 4. 공개 준비 | 설치/업데이트 문서, 성능·복구 테스트 | 운영 기준 충족 후 `enabled` 활성화 |

2단계는 내부 테스트용 4종이며 12종 출시표와 개별 확률이 다릅니다. 테스트 표 버전을 따로 쓰고 공개 출시 표와 혼동하지 않습니다.

### 자동 검증

- 0, 99, 100, 999, 1000, 3999, 4000, 9999 경계값과 가중치 총합.
- 특정 난수 입력에 대한 등급/종 결정, 빈 목록/중복 ID/없는 모델 거절.
- 충분한 반복 추첨 분포 검사는 보조 확인용. 유한 횟수에서 정확히 1%가 나와야 통과하도록 만들지 않음.
- 신규·중복 지급, 잔액 부족, 빠른 연타, 오래된 확인 화면, 재접속, 저장 단계별 실패와 재실행.
- 표 버전 변경 후 진행 중 거래 유지, 연출 취소/재표시 시 중복 보상 방지.

### 실게임 인수 테스트

- 일반/관리자 권한, 리소스팩 수락·거절·다운로드 실패.
- 12종 모두 1인칭·3인칭, 시점 전환, 좁은 길, 경사, 계단, 물, 용암, 낙하, 포털, 소유/타인 땅.
- 탑승 중 로그아웃·사망·순간이동·서버 재시작. 유령 모델/남은 충돌체가 없어야 함.
- 제안 시험 규모: 동시 20/50마리와 장식 펫 포함. 서버 틱 시간, 패킷 전송량, 클라이언트 프레임, 메모리와 회수 후 잔류 엔티티 측정.
- 원거리 애니메이션/파티클 축소, 근거리 전시 수 제한. 시제품 결과로 서버별 최대 수와 성능 합격 기준 확정.
