- 소유권·씨앗 소비·재화·저장 형식을 확장해도 기존 농장과 아이템을 보존합니다.

## 4. P0 — 경제 지표와 시세 안내

### 왜 먼저 필요한가

독립 추첨은 모든 작물의 수익률을 같게 만들지 않습니다. 성장 시간, 수확량, 씨앗 비용과 자동화 여부가 다르기 때문입니다.

현재 기본 설정에서 압력·반올림·이동 시간을 제외한 단순 예시는 다음과 같습니다. 균등한 50~180% 추첨의 평균은 115%, 수확량은 설정 범위에서 균등하게 나온다고 가정합니다. 한 칸을 매번 즉시 다시 심는 경우의 비교이며 실제 수익 예측은 아닙니다.

`분당 기대 순수익 ≈ (평균 수확량 × 기준가 × 1.15 − 씨앗 가격) / 성장 시간`

| 작물 | 계산 | 골드/분/칸 (근사) |
|---|---|---:|
| 양파 | (2 × 90 × 1.15 − 50) / 12 | 13.08 |
| 배추 | (2 × 120 × 1.15 − 60) / 15 | 14.40 |
| 파인애플 | (1.5 × 400 × 1.15 − 240) / 60 | 7.50 |

따라서 장시간 작물을 납품·도감·장식 같은 별도 목적과 연결하거나, 실제 지표를 보고 비용/수확량을 조정해야 합니다. 이번 검토에서는 가격을 바꾸지 않습니다.

### 최소 구현

- 회차 ID, 품목 ID, 시작/종료 가격, 판매량, 판매한 계정 수, 실제 지급 골드, 적용 압력을 집계합니다.
- 관리자 지급·크리에이티브 테스트 거래는 일반 유저 경제 통계에서 구분합니다. 전역 시세 집계에서 제외할지는 별도 운영 설정으로 명시합니다.
- 완료된 거래 기준으로 집계하고, 거래 식별자로 재실행 시 중복 집계를 막습니다. 실패/미확정 거래는 별도 상태로 남깁니다.
- 유저 화면: 현재 가격, 최근 추이, 이번 회차 판매량, 다음 변경 시각, 예상 하락 압력. 무작위인 다음 가격을 확정값처럼 표시하지 않습니다.
- 회차별 파일에 모으고 보관 기간을 제한합니다. 매 틱 파일 기록이나 인벤토리 전수 스캔은 하지 않습니다.

### 관찰할 사항

판매 상위 3종 비중, 작물별 순수익, 최저가에 머문 회차 비율, 신규 유저 첫 땅 구매까지 걸린 시간, 접속자 규모별 공급 압력을 봅니다.
공통 256개 기준은 생산 속도가 다른 품목과 소규모/대규모 서버에 다른 영향을 줍니다. 기본 규칙은 유지하고, 지표가 쌓인 후 품목별 임계값을 옵션으로 검토합니다.
판매를 보류했다가 고가 회차에 몰아 파는 행동은 정상적인 선택으로 보되, 생산 다양화와 판매 다양화를 같은 지표로 간주하지 않습니다.

완료 기준: 여러 계정의 동일 품목 합산, 시세 회차 경계, 재시작, 중복 이벤트, 미완료 거래를 검증하고 화면 값과 저장된 집계가 일치해야 합니다.

## 5. P1-1 — 농장 상태판

진입: 토지 관리인 → 기존 농장 관리 화면 → `작물 현황`. 토지가 없어도 공용 농장 이용 안내를 제공합니다.

첫 버전은 **소유한 땅의 커스텀 작물**만 정확히 집계합니다. 품목별 재배 수, 수확 가능 수, 다음 성숙 예정 시각, 마지막 확인 시각을 표시합니다.
바닐라 작물은 랜덤 틱 기반이므로 정확한 수확 시각을 약속하지 않습니다. 로딩된 범위의 성숙 여부만 표시하거나 첫 버전에서 제외합니다.
청크를 강제로 모두 로드하지 않습니다. 파종·수확·청크 로딩 시 집계하고, 미로딩 영역은 마지막 기록임을 표시합니다. 토지 판매/소유자 변경 시 집계 소유권도 갱신합니다.

구현 연결점: `FarmMenu`, `CustomCrops`, `CropField`, `LandRegistry`. 집계 인덱스가 필요하며, 메모리에서 빠진 청크를 빈 밭으로 표시해서는 안 됩니다.
완료 기준: 청크 이동·재시작 후 숫자가 중복되지 않고, 타인 농장의 상세 정보가 노출되지 않으며, 미성숙/성숙 경계가 맞아야 합니다.

## 6. P1-2 — 다품목 납품 게시판

진입: 광장 게시판 NPC/표지 → 오늘의 주문 → 보유 수량과 보상 확인 → 최종 제출.
처음에는 **계정별 하루 3건 이내, 주문당 2~3품목**, 부분 납품 없이 한 번에 제출하는 안을 권장합니다. 이 횟수는 제안값이며 설정화합니다.

- 작물군을 순환하여 긴 성장 작물도 등장하도록 하되, 초보자가 당일 달성할 수 없는 주문만 받지 않게 합니다.
- 주문은 기준가 기반의 고정 보상으로 만들고 유효 기간 동안 보상·품목·수량을 고정합니다. 시세 갱신을 통한 견적 재추첨은 막습니다.
- 소량 주문·일일 보상 상한으로 일반 판매를 대체하지 않게 합니다. 초기 보상은 골드로 한정하고 즈코인까지 동시에 늘리지 않습니다.
- 납품도 서버에 작물이 공급되는 행동이므로 **품목별 판매량 압력에 포함**합니다. 납품을 통한 공급 페널티 우회를 막습니다. 보상 금액은 일반 판매와 별도 지표로 기록합니다.
- 주문을 위해 상점에서 살 수 있는 재료는 구매→납품 차익이 무제한으로 생기지 않는지 검사합니다.
- 계정 UUID + 날짜 + 주문 ID로 완료 상태를 저장합니다. 재접속·재시작·중복 클릭으로 다시 받을 수 없어야 합니다.
- 일일 경계는 설정된 시간대(기본 Asia/Seoul)로 고정합니다. 자정 이후 오래된 화면의 주문은 제출을 거절하고 새 화면으로 갱신합니다.
- 현재 `TransactionJournal`을 사용하되 납품 상태·아이템 차감·보상·공급 집계를 하나의 거래 기록으로 추적합니다. 자동 복구는 정확히 어느 단계가 완료됐는지 증명 가능한 경우만 합니다.

완료 기준: 수량 부족, 인벤토리 변경, 미완료 저장, 중복 클릭, 자정 전후, 재시작, 공급량 반영, 일반 유저 NPC 진입을 검증합니다.

## 7. P1-3 — 판매 보호

가상 창고부터 만들기보다 기존 인벤토리 거래에 **품목별 판매 제외와 보관할 수량**을 먼저 추가합니다.
예: 당근 64개를 파종용으로 남기면 단품 판매·우클릭 전량·모두 판매에서 초과분만 견적에 포함합니다.
`보유 / 보호 / 판매 가능` 수량을 함께 표시하고, 견적 확인 중 보호 설정이 바뀌면 다시 계산합니다.

납품은 보호 대상도 요구할 수 있으므로 일반 판매와 정책을 구분합니다. 보호된 물량을 사용할 때는 별도 경고와 명시적 확인을 요구하거나 첫 버전에서는 제출을 막습니다.
`Catalog.idOf`로 품목을 식별하고 표시 이름만으로 판단하지 않습니다. 보조 손·이름 변경 아이템에 대한 기존 거래 정책을 유지합니다.
완료 기준: 모든 판매 경로에서 같은 보호 수량을 지키고, 보호 설정이 재시작 후 유지되어야 합니다.

## 8. P2 — 건축·협동 확장

### 상점 즐겨찾기와 검색

이미 건축 색상·가구 품목이 늘었으므로 페이지 이동 횟수를 줄이는 효과가 큽니다. 첫 버전은 별표 즐겨찾기와 분류별 빠른 이동부터 시작합니다.
검색은 한글 입력/취소/검색 결과 없음의 흐름을 정한 뒤 추가합니다. 검색어로 서버 명령을 실행하지 않으며, 상품 클릭 영역과 별표 클릭 영역을 겹치지 않게 합니다.

### 건축 설계도

첫 버전: 작은 창고/온실의 그림·크기·재료·총비용 확인과 자재 체크리스트만 제공합니다. 자동 배치는 다음 단계로 분리합니다.
자동 배치를 추가할 때는 전체 영역 소유권, 높이, 기존 블록/상자/작물, 청크 경계를 사전 검사하고 회전 미리보기와 최종 확인을 거칩니다.
블록 작업은 틱 단위로 나누며, 작업 ID·소비 자재·변경 블록의 이전 상태를 기록합니다. 중단 시 중복 자재 소비나 완료 보상 지급을 막고 복구 범위를 명시합니다.

### 작업자 권한 UI

기존 수확·파종 작업자 역할을 기반으로 초대/해제 UI부터 추가합니다. 수확/파종/건축/상자 접근을 세분화할 때는 기본값을 보수적으로 정하고 소유자만 변경하게 합니다.
방문자의 작물 수확을 허용하는 기존 서리 규칙과 충돌하므로, 건축 권한 추가가 서리 금지로 암묵적으로 바뀌지 않게 합니다.

## 9. 개발 단계와 인수인계

1. **지표 단계**: 회차 집계 저장 + 시세 안내. 경제 관찰 자료를 확보합니다.
2. **편의 단계**: 커스텀 농장 상태판 + 판매 보호. 신규 보상을 넣기 전 거래 흐름을 검증합니다.
3. **반복 목표 단계**: 소규모 다품목 납품 + 일일 한도 + 중복 지급 방지. 관찰 결과로 수치 조정합니다.
4. **소비 목표 단계**: 상점 탐색 개선 + 건축 자재 체크리스트. 이후 자동 배치를 검토합니다.

각 단계는 코드·설정·리소스팩·이전 설정 업그레이드·운영 안내를 함께 변경합니다.
상점/NPC 진입, 일반 유저 권한, 리소스팩 거절, 재접속, 저장 실패를 인수 테스트에 포함합니다. 기존 자동 테스트 통과만으로 실게임 검증을 대신하지 않습니다.
코드를 수정하기 전 동시 작업 내용을 확인하고, 신규 기능은 관련 클래스에 분리해 `MaiTycoonPlugin`과 `Shop`의 수정 범위를 줄입니다.

### 다음 구현의 구체적 시작점

- 회차 집계 데이터와 저장 방식 설계 → 성공 거래 연결 → 기존 시세 화면에 공급 정보 정리.
- 이후 `FarmMenu`에 커스텀 작물 상태판 추가.
- 납품은 별도 주문 모델/저장소/NPC 메뉴로 구현하고 기존 판매·공급 집계 코드를 재사용.
- 보상률, 집계 보관 기간, 주문 한도는 실제 플레이 지표를 보고 확정. 이번 검토만으로 운영 설정을 변경하지 않음.
